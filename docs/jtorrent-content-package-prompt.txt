ARTICLE.JSON
Follow current canonical files. Supported fields include:
- contentKind: "article"
- section
- title
- optional seoTitle, socialTitle, shortTitle
- slug
- description and excerpt
- publishDate and modifiedDate
- author: "Jivaro Torrent Editorial"
- hero: src, srcSmall, alt, dimensions
- dek
- takeaways
- faq (omit when not genuinely useful)
- sources with unique names and HTTPS URLs
- relatedContent with real canonical routes
- ads
- affiliateDisclosure
- featured
- indexing
- draft
- legacyUrls (verified historical routes only)
- schemaType
- comparison
- newAuthority: false for all future content

Preserve an existing publishDate. Change modifiedDate only for a substantive revision. New items default to draft:true until finished. Do not invent a legacy URL.

BODY.HTML
Use body-only semantic HTML inside top-level <section> elements. Include H2 and optional H3 headings. Do not include an H1, document wrapper, metadata, scripts, styles, global navigation, footer, breadcrumbs, TOC, FAQ block, sources block, author box, disclosure, or related cards. Heading IDs and the TOC are generated automatically.

Allowed content includes paragraphs, lists, tables, blockquotes, code, approved callouts, figures, local images, and safe links. Use /go/<validated-slug> for approved affiliate links. Never hardcode affiliate destinations.

EDITORIAL STANDARD
- Normal guide: 2,000–3,500 useful words.
- Comparison: 3,000–5,000 useful words and comparison:true.
- Direct opening, concrete tests, expected outcomes, limitations, and clear decision criteria.
- Distinguish documented product behavior from measurements actually performed.
- No fake tests, prices, screenshots, personal experience, provider claims, ratings, or filler FAQs.
- Use current primary sources for change-sensitive claims.
- Describe authorization and lawful use accurately; do not create infringement or enforcement-evasion guides.

For troubleshooting:
- begin with the exact symptom;
- isolate browser/application, local network, VPN/proxy, provider, source, and swarm failures;
- order tests from safest/easiest to most disruptive;
- state the expected result;
- include rollback instructions for changed settings.

For comparisons:
- define criteria before a verdict;
- compare like-for-like plans, regions, protocols, and conditions;
- timestamp current facts;
- label documentation-only reviews;
- state who should choose and avoid each option;
- do not let affiliate eligibility decide the result.

RESEARCH
Use current primary sources first: official documentation, repositories, specifications, browser/OS documentation, provider pricing/policy/audit pages, regulators/courts for legal claims, and institutional research where appropriate. Search the web for any feature, price, version, ownership, law, audit, product name, or policy that may have changed. Do not cite search snippets, AI summaries, scraped copies, or unverifiable claims.

LEGAL AND SAFETY
BitTorrent is neutral technology. Content may cover authorized torrents, open-source releases, public-domain archives, open datasets, privacy, configuration, troubleshooting, and legal risk. Do not create copyrighted-title download pages, crack/keygen instructions, malware delivery, stolen-account guidance, or instructions primarily intended to bypass enforcement. A VPN or proxy does not make infringement legal, anonymous, or risk-free. Seeding is distribution.

PACKAGE RULES
Return one ZIP that extracts directly into the frontend repository root. Include only created, replaced, or explicitly deleted package paths. Exclude .git, node_modules, dist, caches, OS metadata, screenshots, internal reports, secrets, wrapper folders, and nested ZIPs.

QC
Before delivery run npm run qc and confirm:
- source validation, canonical image discovery, two deterministic builds, and immutable-source checks pass;
- route, dates, author, schema, related routes, sources, hero dimensions, sitemap, RSS, and editorial search index are correct;
- exactly ten historical newAuthority records remain;
- homepage Search Sites and v3/v2 Aggregated Results contracts still pass;
- no content/articles.json or root content-package-manifest.json exists;
- no desktop.ini exists;
- the ZIP extracts directly into the repository root.

SAFE PUBLISHING
Assume PowerShell is already open in the repository root and the ZIP is in the repository root. Use:

& ".\Publish-Content.ps1" -ZipName "<zip-name>.zip" -CommitMessage "Add article: <slug>"

The publisher validates the archive, extracts it, deletes the ZIP immediately, consumes any temporary package manifest, runs deterministic QC, stages only package-owned changes, commits, rebases, reruns QC, and pushes only after success.
